# Components — Net-worth history chart

> Part of the [Odyssey Design System](../README.md) docs. Foundations, tokens and the component catalog live in the README; this file is the per-feature detail.


The dashboard's **Net worth** chart plots a series **reconstructed on read** from data Odyssey already stores — one point per period, each the net-worth figure as of that point's instant — accounts plus, when the response says `PropertiesIncluded`, the estimated value of the properties held, as an asset line of its own. It replaced a fabricated one: an 11-element constant resampled across the account span and scaled so the final point landed on today's real figure, which meant every point but the last was invented and the curve rose for everyone. Reference build: `ui_kits/web/Dashboard.jsx` + `net-worth-data.js`; component states: `components/linechart.html`; page states: `preview/64`, property states: `preview/64b`.

**Property is disclosed, never blended.** When `PropertiesIncluded` is true the header sub-line reads `across N accounts and M properties` (M = every property held now) and the chart's sub-line adds a **composition sentence** for the latest point — the property estimate total, the number of valued properties and the accounts-alone figure. When it is false the caption and accessible name gain `accounts only` and nothing else mentions property. Every property-derived surface reads that response's own flag and fails closed; the page never checks a property claim itself. Unconverted properties join the header rollup as Warnings; unvalued properties are Information rows. (The former Property/Vehicle-account double-count advisory is gone with those account types; a retained, archived Other-asset account's balance can still overlap its property's estimate, which the migration log reports by count.) Only a panel holding both severities gets the headings "Needs attention" / "For your information"; an information-only panel's toggle reads "Net worth notes".

**Reconstruction, not snapshots.** Nothing is interpolated and no past point is scaled by the present figure. The series is derived from stored transactions, estimates and exchange rates as of each period, which makes it correct **retroactively** — a back-dated transaction, a corrected estimate or a fixed rate repairs the history it should have produced. The last point of a series ending today equals the accounts rollup exactly, so the chart and the header can never disagree.

**A point is labelled by the instant it describes.** Net worth is a stock, not a flow: a point covers `[period start, next period start)` and is dated at the **period end**. Mislabelling a financial figure by one period is the original defect in a smaller shape.

**Two conditions are disclosed, never smoothed.** An **understated** point (an account or property had no exchange rate that period, so it contributed 0) draws hollow on dashed segments, and while it sits on an endpoint the delta is withheld — an absolute money difference between two endpoints, one of which is known to be too low, is not a fact. A **revalued** point (an account or property estimate took effect) draws with a tick and keeps the delta, because the step is a real movement. Both get a note sentence in the chart's sub-line, naming the member kind (account, property, or both): the markers and the prose say the same thing, so nothing rests on colour or shape alone. The whole series is also available to assistive technology as a table via `textEquivalent`.

**There is no fallback series.** When the data is not there, the chart is not there — and the copy names which of five causes applies (`NotBuilt` · `NoAccounts` · `NothingConvertible` · `WindowBeforeFirstAccount` · `WindowAfterAllAccountsClosed`), never "no data". When properties are included, `NoAccounts` and the two window causes use property-aware wording ("No accounts or valued properties…"). Unvalued properties never mark a point. A load failure degrades into the header problem rollup rather than a toast; a totals failure withholds the chart unless the money *format* resolved, so a figure never renders in one currency's amount under another's symbol. Loading is the shape plus `Skeleton`, held until both the history and the accounts call settle.

> **Stack reality check.** The series comes from `GET /api/accounts/net-worth-history` (claim `accounts.read`, per-user concurrency limit) returning `mainCurrencyCode` · `interval` · `from`/`to` · `emptyReason` · `points[]` (each with `totalAssets`, `totalLiabilities`, `netWorth` and the `unconvertedAccountCount` / `revaluedAccountCount` / `contributingAccountCount` counts — counts, never lists) · `unconvertedAccounts[]`, plus (#214) `propertiesIncluded`, per-point property counts and `propertyValue`, and `unconvertedProperties[]`. The caller chooses window and resolution (`Daily` · `Weekly` · `Monthly` · `Quarterly` · `Yearly`) bounded by a per-interval point cap; the v1 dashboard sends neither `from` nor `to` and takes the server default of 23 monthly periods back. `preview/64` is the state matrix the page is built against.
