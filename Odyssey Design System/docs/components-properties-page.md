# Components — Properties page

> Part of the [Odyssey Design System](../README.md) docs. Foundations, tokens and the component catalog live in the README; this file is the per-feature detail.


The **Properties page** (`Properties.jsx`, seed + helpers in `properties-data.js`, styles in `properties.css`; page specimen `templates/properties`) is the real-estate and vehicle register at `/properties`, a sibling of Accounts and Contracts. The expanded record runs **Details → Real estate / Vehicle → Estimated value → Contracts → Documents → Smart tags → Events** (see *Components — Property events*).

- **Documents section** (*Property Documents — Backend, Draft v2*; `GET /api/properties/{id}/files`, `ExistingPropertyFile[]`, seed `propertyFileSeed`, helper `propFileRow`). The DS `FilesTable` in its contract configuration: validity columns, no rename, required type on edit, **Detach** (`link_off`) instead of Delete, Download + Copy ID. Unpaged server-side and uncapped — the table pages client-side with `InlinePager`. Empty: *No documents yet — attach the deed, the purchase agreement, a valuation or a warranty* (vehicle copy names registration, inspection, insurance). `issuedBy` is an id only on this response; the Issued-by name comes from the caller's own contacts read and reads *Contact (no access)* without it. The collapsed card carries a **Documents** count beside Estimates and Smart tags. This needs a backend change: the v1 spec's list endpoint carries no count (Non-Goal 4), so `ExistingProperty` must gain a `FileCount`.
- **Attach** (`AddPropertyFileModal`, from the row menu's *Attach documents*). Gated on `properties.update` **and** `files.read`. Two sources behind a `SegmentedControl`: **Upload new** (the DS `FileUpload` — bytes go through the Files API, then attach) and **From Files** (pick stored files). Both apply the shared document allow-list `DOCUMENT_CONTENT_TYPES` (PDF, PNG, JPEG, WebP — the one list contract documents use): a disallowed stored file is disabled with its type named in text; a file already linked is disabled as *Already attached* (the 409). Each picked file takes a `PropertyFileType` (guessed from the name, `propGuessFileType`) and the optional validity fields behind *Add validity*.
- **Nothing derives status from validity** — no expiry badge or "expires soon" roll-up, per the validity rule above, and no reminders (Non-Goal 5).

- **Homeowner association** (*Property Homeowner Association — Backend, Draft v1*; specimen `components/homeowner-association.html`). A real-estate property may name the **Organization contact** that administers it — borettslag, sameie or HOA. Every `RealEstateKind` may carry one; a Vehicle never does. **Write:** the DS **`HomeownerAssociationSelect`** in the dialog's Real estate details, under Cadastral number. It is the `CustodianSelect` shape (`Combobox`, clearable, optional) restricted to **active Organizations**. It sends the scalar `realEstateDetails.homeownerAssociationId` only; `PUT` is a full replace, so the dialog round-trips the stored id and clearing sends `null`. **Change-only rule (§8.3):** the server re-checks the target only when the id changed, so a kept link whose contact has since been archived or re-typed to Person saves unchanged — the picker shows it with the contact's state and *pick another association or clear it to change it*, never as an error. A rejected changed id lands on the field (`RealEstateDetails.HomeownerAssociationId`): 400 *no longer exists* / *archived*, 422 *isn't an organization* — copy never echoes more than the user picked. **Read:** `ExistingProperty.homeownerAssociation` (`{ contactId, name, archived }`, helper `propAssociationFor`) renders as an **InfoTile** in the Real estate section after Cadastral number, in the Organization type's mark (it is a reference, not the record's accent); an archived contact is muted **and** says *Archived contact · since …* in the foot. `null` shows no tile. Visible to every `properties.read` holder, Guest included. **Delete:** removing the contact clears the link (`propClearAssociation`, the `ContactReferenceGuard` statement) — it never blocks the contact delete. Not in v1: search/filter by association, a reverse list on the contact, events on change. Kit tweak *Homeowner association → Save response on a changed id* simulates the 400 / 422.
- **Contracts section** (`GET /api/properties/{id}/contracts`, `PropertyContractLink[]`, helper `conContractsForProperty`). Drawn exactly like the account record's Contracts section: one tile per **contract** (not per party row), overline = contract type, value = contract name, foot = the roles this property holds there in party order · the derived status. Archived contracts are listed, dimmed. Empty: *This property is not a party to any contract.*
- **Claims.** The section needs `properties.read` **and** `contracts.read`. Without the second (Guest) it is **absent**, not empty, and the collapsed card drops its **Contracts** count — `ExistingProperty.ContractCount` is `null`, which is a different fact from 0. The count is distinct contracts, shown only when > 0, like the account card.
- **Delete** detaches rather than blocks. The confirmation lists *N party links on M contracts* and *N document links — the files stay in Files* beside the estimates and smart tags it removes, and states that the contracts are kept and each records a *Party removed* event (`conDetachProperty`: one event per removed row, one shared timestamp, the caller's id, the role only — no property name). Without `contracts.read` the line reads *Any contract party links naming it*, never "none".
