If creating visual artifacts (slides, mocks, throwaway prototypes, etc), copy assets out and create static HTML files for the user to view. If working on production code, you can copy assets and read the rules here to become an expert in designing with this brand.

If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.

## What's here

- `README.md` — product context, content fundamentals, visual foundations, iconography.
- `colors_and_type.css` — every design token as a CSS custom property. Names mirror MudBlazor's `--mud-palette-*` so they wire 1:1 into a custom `MudTheme.PaletteDark` / `PaletteLight`.
- `assets/` — Odyssey logomark + wordmark SVGs and the Odyssey compass logomark rasterized as the favicon set (16 / 32 / 192 / 512).

- `ui_kits/web/` — React + JSX recreation of the Odyssey web app (Blazor WebAssembly / MudBlazor v8). Open `index.html` for a click-thru.

## Quick rules of thumb

- Stack: .NET 10 / Blazor WebAssembly / **MudBlazor v8** / Roboto + Roboto Mono + Material Icons.
- Dark mode is the **primary** surface; light is a first-class alternate.
- **Tide** (phosphor teal) is brand. Sea (sky-cyan) is secondary. **Never** use brand colors to encode income/expense — use mint and coral for those.
- No emoji. No gradients in product chrome. No decorative illustration. The product is a financial instrument; stay quiet.
- Numbers always tabular. **Money is written as the amount followed by its ISO 4217 code — `1,234.56 USD`, never `$ 1,234.56`** (several shipped currencies share a glyph); decimals follow the currency's `MinorUnits`. Negatives use `−` and the expense color — not parentheses. A signed figure leads with the sign plus a figure space (`− 84.00 USD`); an unsigned one carries no leading pad — `money()` / `signedMoney()` handle it.
- **A chart never invents a point.** Every plotted figure is measured as of the instant its label names; a series that cannot be built shows copy naming the cause, not a placeholder curve. Where a figure is known to be incomplete or stepped by a revaluation, the point is **marked by shape and stated in prose** — see `LineChart`'s `kind` and the net-worth history section in `README.md`.
- Icons: Material Icons font (already loaded via Google Fonts). Filled weight at 24px default, 20px in dense rows.
- Spacing: 4px base. Use `--space-1..16`. MudBlazor's `pa-N` / `ma-N` utility classes match 1:1.
- A **smart tag** is a saved transaction filter pinned to a record: the same `TransactionTag` vocabulary, watched from the **account** record and from the **contract** record, by one component (`AccountSmartTagsSection`, `subject="account"` / `"contract"`). The match is **by tag, never by record** — a watched tag's transactions appear under every record watching it — because no `ContractId` exists on a transaction; the section states no contract scope. Per-record caps come from the claim-free `/api/account-limits` / `/api/contract-limits` and are **interpolated, never held as a client constant** (contracts: default 20, ceiling 50 — the filter-array length the resolution query accepts); at the cap the adder blocks and says the number, a refused add shows the server's sentence, and a **degraded (503)** limits read stops the pre-check rather than guessing a ceiling. A tag watched anywhere is **not deletable**: the tags page refuses with one clause per blocker class, **counts only, never the record names**. Specimens: `components/accountsmarttags.html`, `components/contractsmarttags.html`.
- A **budget item has no name of its own**: its transaction tag is required and the tag's name + description are the item's identity on every surface (rows, donut labels, dialogs). Pick it with **`TransactionTagPicker`** — inline create only where there is a submit to stage against. Tag names are unique, case-insensitively, archived rows included. Specimen: `components/transaction-tag-picker.html`.
- A **document's validity** — *Valid from · Valid to · Issued · Issued by* — is four optional, nullable fields on the **link** row, carried identically by account files and contract documents: validity columns + detail well in `FilesTable`, the row menu's Edit dialog, and an *Add validity* toggle per file in the upload modal. Nothing derives a status from them (no expiry badge, no "expiring soon", no filter or sort). `ValidTo` before `ValidFrom`, an unknown issuer, and a year outside the storable range (1000–9999) are per-field errors rendered on the responsible control — never enforced on read. A contract document's edit is narrower: type plus the four fields, **no rename** (`renameable={false}` — the name lives on the FileMetadata), the type **required** (`requireType` — `Signed` is the enum's zero member), and nothing editable at all while the contract is archived. Specimen: `preview/59b-contract-document-validity.html`.
- **Forms mark required only.** A `*` after the label (the `required` prop) is the single obligation marker; nothing is ever labelled "Optional" — absence of the asterisk IS optional. Mark exactly the fields the form's own `submit()` rejects, so the markers and the validation can never drift (a pre-filled required field still gets its `*`). `Modal` explains the marker once, growing a muted `* Required` legend in its footer when the body holds one. Helper text states consequence ("Leave blank if ongoing"), placeholders show an example or what empty means ("No end date") — neither says "Optional". Where a dialog hand-rolls a label instead of using the field's `label` prop, put `<span class="odc-field-req">*</span>` in that label.
- A **user carries at most one profile picture**, set and removed only by themselves — there is no administrator write path. Presence is the `ImageVersion` token on the read DTO, never a probe: `null` → render the initials monogram and issue no request; non-null → *renderable by this caller* (the projection nulls it for an administratively disabled subject, but **not** for a transient lockout). It replaces the monogram on `/account` (control in the profile card + header mark) and on `/users` (list row · detail panel); a load failure falls back to the monogram silently, per row. Control: **`ProfilePictureField`** (`row` = labelled text buttons; `overlay` = the mark is the control, actions on hover/focus with a persistent badge \u2014 what `/account` uses); cropper: the shared **`ImageCropDialog`**, which the contact image also mounts. Specimens: `components/profile-picture.html`, `components/image-crop-dialog.html`.
- A **contact carries exactly one image** — a profile picture for a Person, a company logo for an Organization. One storage slot, two framings: the photo is `cover`-cropped into a circle, the logo is `contain`ed on a **neutral** ground (never cut). The record's accent stays with the record; only the mark's content and, for a logo, its ground change. A load failure falls back to the type glyph **silently** through `Avatar.onError`. Not on `ContactChip` / `ContactSelect` / the finance embed — that boundary is deliberate. Specimen: `components/contact-avatar.html`.
- Record lists are **`RecordCard`**: a dense identity header, and a body whose order is fixed by the component — alert, details (an `InfoTileGrid` of `InfoTile`s), content (one wide tile of prose), then sections under `SectionDivider`s. The body carries the record's **full field set**, header repeats included — at tile scale a labelled value reads as a field, not an echo; foot captions add precision where there is any, a field with no value renders no tile, and tiles never condition on each other (a derived Status tile summarises — it does not replace the tiles it is computed from). One accent per record, taken from its type (`--rec` / `--rec-soft`), inherited by every icon and single-series chart in the card; no type → brand tide. Rules: `components/record-card-rules.html`.

## When you build something new

1. Start the file with `<link rel="stylesheet" href="…/colors_and_type.css">` (or `@import` it). All tokens flow from there.
2. Component vocabulary follows MudBlazor: buttons are `Filled` / `Outlined` / `Text`; cards are `Outlined` or elevated; text fields use `Variant.Outlined`; nav is a `MudDrawer` + `MudNavLink`. Reuse the components in `ui_kits/web/Components.jsx` rather than re-inventing.
3. Layouts: authed views use the App Shell pattern (left `Drawer` 240px is the only chrome — brand lockup at top, primary nav, then a footer group of Preferences / User Account / About; no top AppBar) with a max-width `Large` container. Auth screens are a centered 420px card.
4. Use the icon mappings in `README.md` for product concepts — don't pick new Material Icons for `Accounts`, `Budgets`, `Transactions`, etc.
5. Voice: short, second person, no marketing hype. Error messages follow `"Unable to *do thing*. *Recovery action*."`.
