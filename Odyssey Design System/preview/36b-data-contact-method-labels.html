Contact-method labels

Each row in a contact's Addresses, EmailAddresses and PhoneNumbers collections carries a Label. The three enums were written for a person — Home / Work / Mobile — and Odyssey's contact list is overwhelmingly organizations, where "Home phone" means nothing. Each enum now also carries an organization vocabulary, and every label is scoped to the contact types it is valid for. One invariant holds everywhere: a contact method's label is valid for its contact's type — the picker offers only valid labels, the write path refuses the rest with a 422, and import and type-switch clamp to Other rather than dropping a record.

labelThe three vocabularies · ordinal · scope · meaning
  • tagThe ordinal is the wire contract, not the member name — these enums serialize as integers. 1–19 is the person/shared band, 20+ the organization band, per enum; the bands are not aligned across the three and nothing should assume they are. The scope map, never the ordinal, decides validity. PhoneLabel ordinal 5 is left unused (it was Fax in draft v1).
  • startThe default is the first offered member — defaultFor(kind, type) equals labelsFor(kind, type)[0], so display order and default cannot drift apart. A new organization phone opens on Switchboard; a new person phone on Home.
  • categoryOther is valid for both types in all three enums, unconditionally — that is what makes it a legal clamp target. The clamp writes Other and never guesses a "closest" label, so a Person → Organization → Person round trip is lossy by design.
  • warningWidening a label's scope is free; narrowing it is not. Adding a type to a row leaves every existing row valid. Removing one — or removing a member — breaks the invariant with no migration and no guard: it compiles, passes every test, and silently strands stored rows. A narrowing edit needs its own remap migration in the same commit.
  • keyUnknown keys resolve Other by key, never by position. Organization members are appended after Other in all three registries, so a last-entry fallback would render an undefined ordinal as Branch / Claims / Direct — plausible, specific and wrong.
  • paletteNo new colour. Every entry reuses the neutral oklch(0.74 0.02 250) glyph the label registries already used — a label names a channel, it does not encode status. Meaning is carried by the label text on the tile, never by icon or colour.
  • import_exportvCard. Export emits the nearest standard TYPE token plus X-ODYSSEY-LABEL=<MemberName> — and the parameter only where the label has no standard token of its own, so a file with no organization labels is byte-identical to before. Import prefers the parameter, matched against the enum's member names, then falls back to the standard token, then clamps.
