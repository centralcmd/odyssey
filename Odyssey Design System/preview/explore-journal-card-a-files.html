Direction A — how attachments work

A is always open, so the expanded FilesTable the old card revealed has nowhere to live. Four ways to carry files instead, each shown with two files and with nine. Photos stay in the strip above in every case; each file's kind glyph, colour and label come from the shared account-file registry (accountFileTypes) exactly as FilesTable resolves them — the kinds here are Statement, Contract, Tax, Documentation and Other.

F1 Count only

A count in the footer; files open from the ⋯ menu

What the card does today. Cheapest vertically and identical at 2 or 90 files, but a filename is never visible on the list — you cannot tell an invoice from a photo of an invoice without opening something.

F2 File chips

Files as named chips, in the same row as the tags

Filenames become part of the footer's chip language: kind glyph, name, size, click to open. Adds no new block and no vertical cost for the common one-or-two-file entry; past three the row overflows into a “+6 more” that opens the full list, and long filenames truncate.

F3 Attachment block

A labelled block of named rows below the footer

The closest relative of the old FilesTable: every file named, sized and individually downloadable, in a two-up grid that wraps. Unambiguous and scannable, at the cost of real height — nine files means a five-row block, so it caps at four with a “show all” row.

F4 One media strip

Photos and files in a single strip of tiles

Drops the photo/file distinction in the card: one “what's attached here” strip where a photo is a thumbnail and a file is a named tile. Visually the strongest, and it is how the entry's evidence actually feels — but a tile costs far more width per file than a row, so a nine-file entry wraps to three rows of tiles, and it reads oddest when there are no photos at all.
