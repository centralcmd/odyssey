File types

Files attach in three contexts, each with its own enum. AccountFileType (field FileType on ExistingAccountFile) covers documents filed against an account; TransactionFileType (field Type on ExistingTransactionFile) covers proof attached to a single transaction; TaxStatementFileType (field FileType on TaxStatementFile) covers documents on a tax statement. Each enum carries only a name; the icon and color are a design-system decision, defined once per registry so the Files table, the kind chip, the upload picker, and the file viewer render a kind identically. Hues share the categorical band with the account-type and contact-type registries. Other is the default in each and sorts last.

Document validity metadata — AccountFile

An account file carries four optional, nullable fields describing the document's validity (not the raw bytes). They surface in the Files-table detail well and the inline / upload editors; the ValidFrom–ValidTo pair drives future expiry alerts.

ValidFrom
DateTime?
When the document takes effect — e.g. a policy start.
ValidTo
DateTime?
When it expires — policy end, warranty expiry.
IssuedAt
DateTime?
When the document was issued / signed.
IssuedBy
Guid?
Issuing institution — FK to Contacts.
