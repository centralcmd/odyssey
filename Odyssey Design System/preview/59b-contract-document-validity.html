Contract documents <FilesTable validityColumns issuers renameable={false} requireType />

A contract document carries the same four validity fields an account document does — Valid from · Valid to · Issued · Issued by (a contact id, resolved to a name by issuerFor) — all optional, all nullable, so a document attached before the feature existed prints an em dash rather than a guess. Two things differ from the account table. renameable={false}: the update verb replaces the document's type and validity only, because the name belongs to the FileMetadata the link references — the dialog reads “Edit document” and offers no rename. requireType: the update is a full replacement and Signed is the enum's zero member, so the type carries the obligation * and an empty submit is refused, never defaulted into a claim that the file is the signed agreement. An omitted date clears the stored value; “Valid to” before “Valid from”, and a year outside the range the column can store, are refused inline on the field that holds the mistake. An archived contract refuses both writes, so the table drops Edit and Delete and the section says why.
