Anatomy

  • 1Scrim — .aam-scrim. Full-viewport backdrop (a subtle blur + tint) portaled to <body>. Click it to close; it also catches the focus trap.
  • 2Dialog surface — .aam-dialog. 12px radius, elevation-16, max-width: 520px (wide variants: atm- transaction, afm- upload, fan- analyze, fvm- viewer). Rises in on open.
  • 3Head — .aam-head, a tinted band (matching the footer) holding an optional .aam-lead icon tile, .aam-title (18px medium) and an optional .aam-sub (≤58ch, fills to the ×). The lead tile is brand-tide by default, with .warning/.error tints for destructive dialogs. The title states what the dialog does.
  • 4Close — .aam-x, a 32px round icon button. Esc also closes. Always present.
  • 5Body — .aam-body. A vertical stack (gap: 16px) of fields; inputs recess to the background well. Pairs sit in a <FormRow> (the .odc-form-row grid). Scrolls if tall.
  • 6Footer — .aam-foot. Right-aligned actions: a text Cancel then the filled primary. The primary names the outcome.

Wording conventions

Create
Trigger New X · title New X · primary Create X (e.g. New account → Create account).
Edit
Title Edit X · primary Save changes. The same dialog often does both, keyed on whether an item was passed.
Upload
Files are uploaded, not authored: trigger Upload file · title Upload files · primary Upload / Upload N files.
Process
Verb-specific for one-off flows — e.g. Analyze file. Title and primary share the verb.

Convergence note. Every kit dialog here is built on the shared .aam-dialog shell. The design system also ships a consumable Modal component (.odc-modal) with a hardened focus-trap / scroll-lock / focus-restore a11y layer — see the Modal card. New work should build on Modal; the kit's .aam-dialog dialogs should converge onto it over time so behavior and a11y live in one place.
