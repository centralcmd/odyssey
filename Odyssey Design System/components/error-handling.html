Error display — application/problem+json

Every API error is now an RFC 7807 ProblemDetails body. The client must parse it and show problem.detail — never the raw JSON. This page is the contract for where each field lands. Follow-up to #246.

play_arrowInteractive demo
01

The fix, in one frame

The client reads error bodies as raw strings and shows them verbatim. With standardized JSON bodies, users now see the wire format in toasts and inline errors. Parse it; show the human-readable detail.

closeToday — raw string
error
Not Found: 404 {"type":"https://odyssey.app/errors/not-found","title":"Not Found","status":404,"detail":"Account ID 42 not found."}

ReadAsStringAsync → the whole JSON envelope is interpolated into the snackbar. Unreadable, leaks type URIs and status noise.

checkTarget — parsed detail
error
Account ID 42 not found.

ReadFromJsonAsync<ProblemDetails> → show detail only. One clean sentence; the envelope stays on the wire.

02

What the helper reads — and how it routes

One shared helper reads the response, returns a friendly message + the optional code extension + any field errors, and every call site routes through it. First, what it reads from the body:

{
  "type": "https://odyssey.app/errors/feature-disabled",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "Account totals are turned off for this workspace.",
  "code": "feature_disabled"
}
detail show
The message the user reads — toast body, inline field error, feature-disabled block. The one field rendered verbatim.
title show*
Heading on rich surfaces only (the ProblemAlert / feature-disabled block). Skipped in toasts — too terse to add signal.
code extension branch
Machine string for branching — feature_disabled, tax_statements_disabled. Picks the surface; never shown to the user.
errors extension inline
The field → messages map on a validation problem ({ "Custodian": […] }). Present on a 4xx → route each message to that field's error line instead of a toast.
status route
Picks the surface (see below) and the fallback reason phrase. Never interpolated into copy.
type dev
Diagnostics / an optional docs link. Not surfaced inline.
— absent —
No detail, or a body that isn't JSON → fall back to the HTTP status reason phrase ("Not Found", "Service Unavailable"). Guard the parse; never show a parser exception.
Then: route by status class

The surface follows the status, not the endpoint. The principle: things the user can fix go inline; things they can't go to a toast.

2xx→
Success toast“Account created.” The dialog closes.
4xx + field→
Inline field errorA validation problem with an errors map — anchor each message to its field. Dialog stays open so the user can fix it.
4xx · no field→
Error toastNothing to anchor to (e.g. 403 / 404) — show detail.
5xx / network→
Error toastServer-side; the user can only retry. Show detail, or the reason phrase when the body isn't JSON.
503 + code→
Feature-disabled blockAn in-place ProblemAlert keyed on the code extension — overrides the toast/inline split above.
03

The five surfaces

Each call site below names the source location from the issue, and the policy row it follows. Severity follows status: a 4xx/5xx failure is coral; a turned-off feature is informational, not an error.

A · Generic API failure Toast severity="error"
error
Couldn't save the account — the name is already in use.

ApiClient.SendAsync — a 5xx (or a 4xx with no field to anchor to) shows problem.detail, reason phrase if absent. Auto-dismiss; manual close stays.

B · Body isn't JSON — fallback
error
Service Unavailable. Please try again.

A gateway returns HTML / empty body → ReadFromJsonAsync would throw. Catch it; use the status reason phrase. Robustness, not a happy path.

C · Inline field error — custodian validation CreateAccountDialog
add_card
New account
Custodian Optional
The selected contact is archived and can't be used as a custodian. Pick an active one or clear the field.

4xx with a field target. The validation problem's errors map names Custodian, so the message routes to that field's error line — not a toast — and the dialog stays open. Extract from errors; never assign the full JSON to _custodianError.

D · Feature-disabled 503 — Accounts totals code = "feature_disabled"
Option 1 · ProblemAlert, info severity
Totals
info_outline
Account totals are turned off

Totals across accounts aren't being computed for this workspace right now. Individual account balances are unaffected.

Calm, in-place, keeps the panel's frame. Best when the surrounding screen still works.

Option 2 · muted EmptyState
Totals
toggle_off
Totals unavailable
Account totals are turned off for this workspace.

Reads as "nothing here" — better when totals are the panel's only content.

Recommendation: ProblemAlert (Option 1). A disabled feature is a state to explain, not an absence to apologize for — and it holds the panel's shape so the layout doesn't jump. Branch on the code extension (or status 503) — the deleted ErrorResponse DTO is gone.

E · Feature-disabled 503 — File Analysis dialog FileAnalysisDialog
document_scanner
Analyze statement
info_outline
Statement analysis is turned off

Automatic transaction extraction isn't available right now. You can still upload the file and add transactions manually.

Same pattern, inside the dialog body — replaces the analysis UI, leaves a sensible fallback action. The 503 branch is unchanged by #246; optionally tighten it to the code extension for specificity.

04

Rules

check_circleDo

  • checkRoute 4xx field errors inline via the errors map; send 5xx and fieldless 4xx to a toast.
  • checkFall back to the HTTP status reason phrase when detail is missing or the body isn't JSON.
  • checkKeep the dialog open on an inline error so the user can fix and resubmit.
  • checkBranch feature-disabled flows on the code extension (or status 503) via the shared helper.

cancelDon't

  • closeShow the raw JSON envelope in a toast or inline error.
  • closeFire a global toast for a 4xx that names a field — anchor it inline instead.
  • closeInterpolate status codes or type URIs into user copy, or let a parser exception surface.
  • closeReference the deleted ErrorResponse DTO — it's gone.
