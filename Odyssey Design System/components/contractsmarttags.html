On a contract the match is scoped by the server: a transaction reads here only if it carries a watched tag, is dated inside the term, and names a contact party as its merchant. The section restates the response's scope (the date window and the party-contact count) under the bar and maps emptyReason to a state — NoSmartTags is the existing first-tag empty state; NoContactParties and InvalidTerm use blocked, each with the one action that fixes it. Paging, search and sort go to the server, so the table uses a footer Pager over page.totalCount, and the bar's net total is the server's summary.totals passed as netTotal — every match, never a page sum. Mixed currencies have no single sum, so the host passes none and the bar shows the count only. Without transactions.read the read is never issued: the chips stay, the table is replaced by a sentence naming the claim.
