One cropper, two surfaces. The dialog was extracted from the contact-avatar dialog when the user profile picture arrived: two copies of a cropper on an untrusted-input path drift, and the copy with fewer eyes on it drifts first. The caller supplies the labels, its own megabyte constant and an onUpload delegate; the dialog owns the source caps, the stage, the re-encode and the failure rules. fit is chosen from what the image is — cover for a photograph, contain for a logo, which is never cut.

Every control id is per instance. Generated with React.useId, because a shared component mounted twice with hardcoded ids breaks <label for> and aria-describedby on both mounts. The three ranges are labelled and arrow/Home/End operable by construction; pointer drag on the canvas is an addition, never the only affordance. The <canvas> is aria-hidden, so the preview state is written out as text beside it.

One validation rule, two destinations. A failure attributable to the file control renders on that control and moves focus to it. A server or network failure — including a 413, a 409 or a 429 — goes to the role="alert" region, carries the server's message verbatim, and does not move focus: the dialog stays open and the crop is never lost.

The cap is a min, never a max. The dialog resolves min(instance upload cap, surface megabytes) itself and states the result in its subtitle. A surface may tighten an instance-wide cap; it must never override one an administrator has lowered.
