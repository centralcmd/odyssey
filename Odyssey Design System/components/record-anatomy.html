Row lifecycle

Rest eastrow click View (detail) eastmenu · Edit Edit eastsave Saved flash east~2.2s Rest
  • 1Rest. One line per record: optional 36px leading Avatar, then the page's columns, then the trailing action cluster — expand chevron + overflow menu (ActionMenu). The whole row is a click target for expand.
  • 2Saved flash. After a save the row collapses back and a transient Saved chip (income tone, dotted) appears beside the primary cell for ~2.2s (savedFlashMs). No toast, no dialog — confirmation lives in the row.
  • 3Expanded row. Tide tint rgba(79,215,203,.06), bottom rule suppressed so row + panel read as one unit; the chevron rotates 180°. Accordion by default — opening a row closes the previous one (multiOpen is opt-in).
  • 4View mode — .acct-detail. The full record, read-only: a 2-column .meta-grid of MetaTile wells (recessed to background, 11px uppercase label / 15px value). Always two tiles per row — no spanning; long values wrap inside their tile. Panel sits on the background well under a 1px primary top rule.
  • 5Edit mode — .acct-detail.acct-edit, swapped in place of the detail panel (never a dialog). Head is edit icon + Edit X; fields sit in a 2-column .edit-grid, each field occupying a single column (no full-width spanning), inputs recessed to the same well color. Long-text fields (descriptions, notes) render as resizable multi-line textareas via Field multiline. The expand chevron disables while editing.
  • 6Edit actions. Right-aligned: text Cancel (back to view mode, unchanged) then filled primary Save changes. Same wording as the Edit dialogs — see the dialog anatomy card.
  • 7Overflow menu — ActionMenu, opened from the kebab. Fixed order: View details / Collapse (hidden while editing), Edit, record-specific items (Archive / Restore), then a separator and Delete — always last, danger-tinted.

Conventions

Owned
The primitive owns sorting (SortHeader), accordion expand, the view ⇄ edit swap, the overflow menu, delete, and the Saved flash. Pages never re-implement these.
Per-page
A page declares only its columns, the MetaTile detail grid, and the edit fields (renderDetail / renderEdit). Both panels may hold custom content but keep the panel shape above.
Entry points
View: click the row or chevron. Edit: Edit in the row's overflow menu (also from a collapsed row — it expands straight into edit).

Where it's used. Contacts, Transaction tags, Currencies, Exchange rates and Users all render this one primitive (RecordTable) — see the live, clickable card next to this one. The files surface (FilesTable — Accounts detail, Transaction panels, Files page) is a preset of it: same lifecycle, with Preview (the document viewer) as a file-specific menu item distinct from View details. If a new admin page needs a sortable list with per-row view/edit, it should consume RecordTable, not fork the pattern.
