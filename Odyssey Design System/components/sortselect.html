SortSelect <SortSelect variant="split" /> · the spec anatomy
Field selector (visible “Sort by” label inside the trigger) + a direction toggle whose label is typed to the field. Both bind one {key, dir} — the same value the table headers drive on RecordTable pages. Changing the field applies its natural default direction; the toggle flips it.

Direction is never conveyed by the arrow alone — the typed words are visible, and the aria-label always carries the plain word (“ascending” / “descending”). SortHelpers.defaultDir is the single authority, consulted identically by the dropdown and by header-click column changes.
Variant · segmented
Both directions visible at once — reads fastest, costs the most width. Same one-{key,dir} contract.
Variant · menu (combined)
One trigger; the popover lists Field then Direction sections. Most compact — two clicks to change direction.
Single-field page · same anatomy
With one curated field (e.g. Transaction tags) the control keeps the same field-select trigger + direction toggle as every other page — the dropdown simply offers that single option, so the filter bar stays consistent across pages.
